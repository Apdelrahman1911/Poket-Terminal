# Output copy and session status

- **Copy output** opens one transient read-only, selectable snapshot. Choose **Copy visible** (current xterm screen/selection) or **Copy recent** (active tmux pane's recent history), then **Copy text**. **Select all** / the native selection menu works when clipboard permission is denied or unavailable. Desktop xterm selection is unchanged.
- Snapshots are capped at **200 physical lines /64KiB UTF-8** and explicitly marked when truncated. Recent capture is authenticated and CSRF-protected, read-only, one subprocess globally with **no waiting queue**, a5s/128KiB native-output cap and64KiB response cap. It never sends keys, attaches a PTY, or writes terminal text to SQLite/files. Full-screen applications may not retain their prior screens in tmux history; this is not a Codex transcript export.
- Close, switch, disconnect, background, logout and disposal discard the snapshot/capture. Clipboard writes are user-triggered, globally single-flight and bounded; late capture/write completions cannot populate another terminal's snapshot or feedback. An OS clipboard write **already dispatched cannot be cancelled**; closing does not erase the system clipboard. No asynchronous capture automatically writes the clipboard.

## Three independent status dimensions

1. **Lifecycle:** starting/not started, running, stopping, stopped, exited, verified start/exit error, or unknown/refreshing. Certain failed starts keep stopped `start_failed` metadata, use no running slot and can be deleted. Unknown spawn state retains its slot. Native exit status/signal distinguishes errors; a missing job/reboot is not inferred to have completed successfully. Multi-pane sessions remain alive while any pane lives.
2. **CLI activity:** new Codex launches add only `-c 'tui.terminal_title=["activity","status"]'`. The historically tested 0.153.4 native title reports `Ready`, a single known spinner followed by ` Working`/` Thinking`, or `[ . ] Action Required` / `[ ! ] Action Required`. These map to ready-for-prompt, working, awaiting input. **Ready is not last-task success. Nonfatal CLI/API errors are not reported by this signal.** No screen-text scanning, hook payload/trust changes, new model calls or global Codex edits.
3. **Browser:** controlling, view only, connecting/detached, suspended, or not attached. A live process is not necessarily working; an unattached/silent session is not inferred to need input.

Activity eligibility requires the app's versioned **pane-local** marker, current foreground command exactly `codex`, and that pane/window both active. Replaced programs, inactive panes, legacy/uninstrumented sessions and unknown native titles yield unknown/activity unavailable. Existing jobs are **not restarted or modified for instrumentation**. The tmux inventory normalizes to an allowlisted enum internally: arbitrary titles/commands never enter the HTTP catalog or logs. This is advisory native CLI state, not an authentication/security boundary.

The visible page uses one completion-scheduled3s metadata poll, with one request/timer and an8s request deadline; it is aborted/stopped in the background or on logout. A failed/stale refresh displays unknown, not cached working. Pages contain at most20 cards; one additional selected metadata row preserves the selected terminal while paging. No inactive output capture/renderers/PTYs/watchers. The native activity map holds at most20 enums, without retained event histories. Database schema/dependencies, owner agent settings, 500/2000 history limits, input/ACK/control bounds, Delete and scrolling remain unchanged.

Verification uses isolated synthetic sessions, native title fixtures, production-build browser and minimal-env foreground service. Historical CLI title checks used isolated loopback mocks, not paid model calls. These browser checks were not rerun for publication. Physical-phone native clipboard behavior remains a manual check; the browser fixture is mobile emulation.

## Card colors

Static accents and readable labels distinguish blue working, amber awaiting input, green ready, violet starting, orange stopping, grey stopped/exited, and red verified error. Muted teal with a dashed accent means **Running · activity not reported**, not failure; grey-violet with a dotted accent means stale/unconfirmed state. Selection uses an independent light border and keyboard focus an outer outline, preserving the state tint. Lifecycle/error states override activity; stale metadata cannot show cached working. Existing/older Codex sessions are not retrofitted or restarted: only new instrumented Codex sessions report native activity. Generic shells remain unreported. No extra polling, retained metadata, terminals, animations or backend changes.
